# GS2026のLCDにLoRa経由のGPSを表示する

`src/modules/LCD/main.cpp`はGS2026基板用。元の拡張子なしの`main`を、
PlatformIOでコンパイルできる`main.cpp`に変更した。

## 構成と書き込み

```text
Tracker等のGPS → LoRa無線 → LoRa受信基板 → CAN → GS2026 → LCD
```

ESP32-S3のLoRa2026基板とGS2026を使う場合：

```sh
pio run -e LoRa_ESP_CAN_Ground -e LCD
pio run -e LoRa_ESP_CAN_Ground -t upload --upload-port <LoRa基板のCOMポート>
pio run -e LCD -t upload --upload-port <GS2026基板のCOMポート>
```

旧RP2040 LoRa基板では`LoRa_ESP_CAN_Ground`の代わりに`LoRa_CAN`を使う。
`LoRa_ESP_Ground`、`LoRa_ESP_Flight`と`LoRa`環境はUSBシリアル用の設定を維持し、
新しいCAN用環境では`LORA_USE_CAN=1`でCANとUSBの両方へ転送する。
CANのパケット種別の修正も送信側に必要なため、受信基板にも今回のプログラムを書き込む。

LoRa基板とGS2026のCANH同士、CANL同士、GND同士を接続する。
CANは125kbps、バスの両端に120Ωの終端抵抗を設定する。
無線側のチャンネルなどは送信機と一致させる。
現行LoRa受信プログラムはTracker用のチャンネル3。
MissionBusを使う場合は送受信側のチャンネルを合わせる
（現行MissionBusは11で、`lora.begin()`もコメントアウトされている）。

## 配線

GS2026は`hardware/modules/GS2026/GS2026-backups/GS2026-2026-08-28_173010.zip`
内の`GS2026.kicad_pcb`で確認。LCD501はSC2004CSWB-XA-LB-G、20文字×4行。
Arduinoの[LiquidCrystal](https://github.com/arduino-libraries/LiquidCrystal)
1.0.7を使い、4ビットのパラレル接続で駆動する。

| 信号 | GS2026のGPIO |
| --- | --- |
| LCD RS | 8 |
| LCD E | 18 |
| LCD DB4 | 6 |
| LCD DB5 | 7 |
| LCD DB6 | 5 |
| LCD DB7 | 4 |
| CAN RX | 44 |
| CAN TX | 43 |
| STAT LED | 42 |
| ERROR LED | 41 |

LCDのR/Wは基板上でGNDに接続されている。
LoRa2026のCANもRX=44/TX=43。旧RP2040 LoRa基板はRX=23/TX=22。
GS2026のモジュールIDは`0x47`、地上局ユニットIDは既存GSと同じ`0x64`。

## 表示と受信形式

2秒ごとに次の2画面を切り替える。表示待ちでCAN受信を止めず、
最新のデータを100msごとに表示へ反映する。

```text
GPS LAT / LON
Lat: 35.708736
Lon: 139.717072
CAN RX U:61 0s
```

```text
GPS ALTITUDE
Alt: 1234.0 m
GPS altitude [m]
CAN RX U:61 0s
```

- WCPPのGPSテレメトリ`'M'`、コンポーネント`0x15`を受信する。
- `LA`=緯度[度]、`LO`=経度[度]、`AL`=GPS高度[m]。
  floatと整数を読み取り、3項目が揃った同一パケットだけを採用する。
  非数、無限大、緯度経度の範囲外、欠損項目は採用しない。
- Tracker (`0x61`)・MissionBus (`0x62`)など送信元を限定せず、
  最後に受け取ったGPSを表示する。`U`は元の送信元ユニットID。
  複数機体が送る場合は最後に到着した機体の値になる。
- 未受信時は`Waiting for GPS...`を表示する。
  5秒以上更新がなければ最終値を残して`STALE`と経過秒数を表示する。
- 現行GPS送信コードには測位有効フラグがないため、`CAN RX`は
  データの受信を意味し、測位成功を保証しない。初期値の0も受信値として表示する。
  緯度経度の小数6桁表示は元のfloat32データの精度を高めるものではない。

共通CAN送信処理も、CAN IDに`packet_id()`だけでなく`type_and_id()`を載せるよう修正。
従来はテレメトリビットが落ち、受信側でコマンドとして扱われていた。

実機では、起動直後の未受信表示、GPS受信、2秒の切替、送信停止後5秒での
`STALE`表示、送信再開後の更新を確認する。

## 検証結果

- `pio run -e LCD -e LoRa_ESP_CAN_Ground`：両環境でビルド成功。
- `pio run -e LoRa_CAN`：旧RP2040用もビルド成功。
- 共通コード・依存ライブラリの既存警告は残っている。
- `src/library/test/test_can_bus`に実際のCAN分割・再結合処理を使う回帰テストを追加。
  GPSテレメトリ、ローカルテレメトリ、コマンドの種別とバイト列保持を検査する。
  Xtensaコンパイラで構文確認済み。ホスト用C++コンパイラがないためテスト実行は未確認。
- 基板への書き込み、実機のCAN通信とLCD表示は未検証。
