# IGN点火シーケンスの安全性・動作修正

## 概要

IGNコンポーネントの点火コードを確認し，起動時のGPIO状態，点火シーケンスの時間管理，異常時の停止，センサ初期化，テレメトリおよびテストを修正した．

- 修正日: 2026-08-29
- 対象モジュール: `IGN`
- モジュールID: `I` (`0x49`)
- ユニットID: `0x40`
- IGNコンポーネントID: `36` (`0x24`)

KiCadおよび回路図は，依頼に従って確認対象に含めていない．

## 確認した主な問題

- 点火シーケンスとGPIO制御が直接結び付いており，時間境界や異常系を単体テストしにくかった．
- タスク処理が遅れた場合，警告フェーズを飛ばしたり，予定時刻を過ぎてから点火出力を有効にしたりする可能性があった．
- 点火出力の停止が通常のIGNループ処理に依存していた．ログ送信やパケット処理が停止すると，出力停止が遅れる可能性があった．
- 起動直後のGPIOを明示的な安全状態へ設定する処理が不足していた．
- INA226の接続失敗および校正失敗が点火開始条件に反映されていなかった．
- `TwoWire`をコンストラクタで受け取っていたが，INA226へ渡していなかった．
- サンプリング周波数が0または過大な場合の検証がなく，0除算や0 ms周期になる可能性があった．
- ピン番号の重複や無効値を検出していなかった．
- モジュールIDとコンポーネントIDが資料と実装で一致していなかった．
- Unityテストに必要な`setUp()`と`tearDown()`がなく，nativeテストを実行できなかった．

## 変更内容

### 1. 点火シーケンスのステートマシン化

ハードウェアに依存しない`IGNSequence`を追加し，状態遷移と出力要求を一か所で管理するようにした．

| フェーズ | 値 | 時間 | 動作 |
| --- | ---: | ---: | --- |
| Startup | 0 | 1秒 | ブザー連続，NORMAL点灯 |
| Countdown | 1 | 30秒 | 1秒周期で0.2秒ブザー，NORMAL同期点滅 |
| Final | 2 | 5秒 | ブザー連続，NORMALを5 Hzで点滅 |
| Ignition | 3 | 3秒 | HIGHとLOWを有効化して点火 |
| Done | 4 | 無期限 | 点火出力停止，NORMALを2秒周期で短時間点灯 |
| Disarmed | 5 | 無期限 | 点火出力停止 |
| Fault | 6 | 無期限 | 点火出力停止，NORMALを2 Hzで点滅 |

通常動作では，全コンポーネントの初期化成功後，最初のIGNループからフェーズ0を開始する．開始から点火までは最短36秒である．

タスクが遅延した場合は一度の更新で複数フェーズを進めず，各警告フェーズを所定時間実行する．したがって，遅延によって点火が早まることはなく，安全側である遅い時刻へ延長される．

### 2. 起動時のGPIO安全化

`prepareSafeOutputs()`を追加し，`kernel::begin()`より前に点火関連GPIOをLOWへ設定するようにした．

GPIOは次の順序で初期化する．

1. NORMAL，HIGH，LOWの出力ラッチをLOWへ設定する．
2. 各ピンを`OUTPUT`へ変更する．
3. 内部の出力状態キャッシュをLOWとして初期化する．

これにより，カーネルや各タスクの初期化に失敗した場合も，点火出力は安全状態のままとなる．

### 3. 点火出力の安全な切り替え

- 停止時はLOW側を先にLOWへ戻し，その後HIGH側をLOWへ戻す．
- 点火時はHIGH側を先に有効化し，LOW側を最後に有効化する．
- LOWだけが有効になる不正な要求は，HIGH・LOWの両方を停止する安全状態へ変換する．
- GPIO更新をクリティカルセクションで保護し，自動遮断と通常ループが競合しないようにした．
- 中止または自動遮断後の古い状態情報によって，再び点火出力が有効にならないようにした．

### 4. 独立した3秒自動遮断

点火フェーズへ入る前に，高優先度の専用FreeRTOSタスクを起動する．点火開始から3秒後，通常のIGNループ，ログ処理およびテレメトリ送信とは独立してHIGH・LOW出力をLOWへ戻す．

専用遮断タスクの起動または通知に失敗した場合は，点火せずFaultへ移行する．

### 5. 初期化と設定値の検証

- 渡された`TwoWire`をINA226のコンストラクタへ渡すようにした．
- INA226の`begin()`失敗を検出するようにした．
- INA226の`setMaxCurrentShunt(4, 0.020)`失敗を検出するようにした．
- センサ初期化または校正に失敗した場合は点火を開始せず，出力をLOWへ固定する．
- サンプリング周波数を`1～1000 Hz`に制限した．
- NORMAL，HIGH，LOWピンの負値，`no_pin`および相互重複を拒否するようにした．

### 6. モジュール起動処理の修正

- `Serial.begin()`直後に`prepareSafeOutputs()`を呼ぶようにした．
- モジュールIDを資料に合わせて`I`へ統一した．
- `kernel::begin(module_id, true)`としてモジュールID検査を有効化した．
- `Wire.begin(17, 16)`の戻り値を検査するようにした．
- Pressure，Logger，HeaterおよびMainの初期化成功後に`ign.begin(true)`を呼ぶようにした．
- いずれかの初期化に失敗した場合はIGNを開始せず，点火出力を停止する．
- 起動直後にフェーズ5を送信していた問題を修正し，最初のIGN状態テレメトリからフェーズ0になるようにした．

### 7. 通信コマンドに関する変更履歴

検討途中では，開始コマンドと緊急停止コマンドを受信する処理を追加した．その後の指示により，通信経由の緊急停止コマンド`A`を削除した．さらに，起動時にフェーズ5で待機し続ける問題への対応として，開始コマンド待ちも削除した．

現在の最終実装は次のとおりである．

- 通信による開始コマンド: なし
- 通信による緊急停止コマンド: なし
- 全コンポーネントの初期化成功後に自動でフェーズ0を開始
- 内部エラー時に使用する`abortSequence()`は保持
- 点火開始から3秒後の独立自動遮断は保持

### 8. テレメトリの追加・整理

電力テレメトリ`I`に加え，点火シーケンス状態テレメトリ`S`を追加した．状態変化時と1秒周期で送信する．

| エントリ | 内容 |
| --- | --- |
| Ph | 現在のフェーズ |
| Et | 現在のフェーズの経過時間(ms) |
| St | シーケンス開始からの経過時間(ms) |
| Rt | 点火までの残り時間(ms) |
| Bz | ブザー出力状態 |
| Ig | 点火出力状態 |
| Hi | HIGHピンへの要求状態 |
| Lo | LOWピンへの要求状態 |
| Nl | NORMALピンへの要求状態 |
| Ok | 初期化成功かつFaultでないことを示す状態 |
| Ts | タイムスタンプ(ms) |

`Hi`，`Lo`および`Nl`はGPIOへ要求したソフトウェア上の状態であり，電気的なreadbackではない．

### 9. IDと資料の整合

- IGNコンポーネントIDを`36`へ統一した．
- IGNモジュールIDを`I` (`0x49`)へ統一した．
- `docs/components.md`へシーケンス，ピン，状態値およびテレメトリ仕様を追加した．
- `docs/modules.md`のIGNコアを`ESP32Core`へ修正し，Ignite IDとして`36`を記載した．
- PlatformIOのデフォルト環境へ`IGN`を追加した．

## テスト追加

ハードウェア非依存の`IGNSequence`に対し，次のnativeテストを追加した．

- フェーズ境界（1秒，31秒，36秒，39秒）の状態と出力
- 点火更新が遅れた場合に期限後の点火出力を行わないこと
- 中止時にHIGH・LOW出力要求が停止すること
- Fault時にHIGH・LOW出力要求が停止すること
- 同一起動中の再開始を拒否すること
- `millis()`の32 bit周回後も経過時間を正しく扱うこと

既存nativeテストを実行可能にするため，Unity用の`setUp()`と`tearDown()`も追加した．

- KiCad，回路図および基板配線の確認

実機試験を行う場合は，最初にイグナイタと点火用電源を外した状態で，HIGH・LOWの出力順序，36秒の警告時間および3秒後の遮断をオシロスコープまたはロジックアナライザで確認する必要がある．

## 補足

- `Disarmed = 5`は内部状態として残しているが，通常のモジュール起動では`ign.begin(true)`を使用するため，最初のIGNループでフェーズ0へ移行する．
- 通信経由の緊急停止機能は最終実装に含まれない．
- 3秒自動遮断はソフトウェア上の高優先度タスクであり，外部の物理的なキルスイッチやハードウェアタイマーの代替ではない．
- ビルド時にリポジトリ既存コード由来の警告が出力されるが，IGN環境のリンクおよびファームウェア生成は成功している．
