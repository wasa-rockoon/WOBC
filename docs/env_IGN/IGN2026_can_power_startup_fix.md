# IGN2026：CAN側給電時の起動不良とソフト対策

記録日：2026-09-06

## 症状

- 対象はIGN2026基板。
- USB給電ではSTATなどのLEDが動作し、正常に起動する。
- 別基板からCANコネクタ経由で3.3 Vを供給すると、RESET LEDが一度点灯した後、STATなどが動作しない。
- CAN側給電のまま手動でResetすると動作する。

## 実施した修正

### 1. IGNの初期化前に1秒待機する

対象：`src/modules/IGN/main.cpp`

`ign.prepareSafeOutputs()`で点火出力をLOWに設定した後、`delay(1000)`を追加した。カーネル、CAN、周辺機器の初期化は、この待機の後に開始する。

外部から供給される3.3 V電源や周辺機器の立ち上がり時間を確保するための対策。既存のSPI初期化後の1秒待機は残しているため、起動処理の待ち時間は従来より1秒増える。

### 2. CAN受信開始前に受信キューを準備する

対象：`src/library/core/can_bus.cpp`、`src/library/core/can_bus.h`

修正前はCANドライバを開始してから受信キューを作成していた。この間に別基板からフレームが届くと、受信コールバックが未準備のキューにアクセスする可能性があった。

修正後の順序：

1. 受信キューを作成する。
2. キュー作成の成功を確認し、パケットのリスナーを登録する。
3. CANドライバを開始する。

併せて、受信キューハンドルを`nullptr`で初期化した。キュー作成失敗時は`cbInit`エラーを通知してCAN開始を中止し、キューがない状態ではループと受信処理を行わない。

この修正は共通の`CANBus`に入っているため、IGN以外の利用モジュールにも適用される。今回のビルド確認対象はIGNのみ。

## 確認結果

- `pio run -e IGN`：成功。
- 修正後、ユーザーからCAN側給電で動作したとの報告あり。
- 書き込み操作・実機試験は本記録の作成者側では実施していない。

## 原因の確定状況

起動前の待機とCAN初期化順序の修正を同時に適用しているため、どちらが今回の症状に効いたかは未確定。電源電圧やENの波形も未測定であり、電源側に問題がないと確定したわけではない。

RESET LEDの一度の点灯だけでは、アプリケーションの起動成功は判断できない。8月20日の設計バックアップでは、このLEDはTPS3820のリセット出力と接続されている。

CPUがコード実行を開始する前の電源・リセット不良は、今回追加した待機では解消できない。

## 再確認する場合

- USBを接続せず、CAN側給電で電源投入を複数回行い、手動ResetなしでSTATとCAN通信が動くことを確認する。
- 供給元基板とIGN2026の同時起動、および供給元基板が先に動作している場合を確認する。
- 再発した場合は、IGN2026側の3.3 VとENの立ち上がり波形を測定する。
