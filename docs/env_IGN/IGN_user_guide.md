# IGNモジュールの使い方 — 開始条件・設定・アボート・故障時の動作

## この資料の対象

この資料は、IGNの操作と設定を初めて確認する人向けの説明書です。
「シーケンス開始」は警告音・カウントダウンの開始、「通電」は点火出力を有効にすることを意味します。この2つは別の時刻です。

| 項目 | 対象 |
|---|---|
| 参照ブランチ | `feature/IGNsrc` |
| 参照コミット | `de3f6b9b10e26522e1cb90c0aeada64bb0f8a8ce` |
| 作成日 | 2026-09-16 |
| 対象モジュール | `src/modules/IGN/main.cpp`、ESP32-S3、PlatformIO環境`IGN` |
| 点火制御のクラス | `component::IGN`。別の`Nichrome`クラスや旧`components/ignition`のプログラムとは区別する |
| MissionBus | 既存のGPSパケットを利用。ファームウェア変更・書き換え不要 |

**作成時の作業ブランチは`feature/Missionsrc`です。そこには対象のIGNソースや`IGN`ビルド環境がありません。以下の設定・コマンドは、上記IGN実装を含む作業コピーで使用してください。** 本文のソースパスは、その版での位置を示します。

## 1. 最初に覚えること

1. **電源を入れただけでは開始しません。** まずフライトピン挿入中のHIGHを認識し、その後、抜去によるLOWを認識する必要があります。
2. ピン抜去中に、下記の通常条件Aまたは代替条件Bが成立するとシーケンスに入ります。
3. シーケンス開始後、最短66秒の警告を経て通電します。
4. 開始後にフライトピンを再挿入してGPIOがHIGHへ変化すると、アボートします。
5. 一度開始要求を出した通常のIGNモジュールは、同じ起動中には再試行しません。再挿入して抜き直すだけでは再開始できません。

### 開始条件を一枚で見る

```text
共通条件：起動後にHIGHを認識 → LOWを認識 → 現在のGPIOもLOW
                               │
                  ┌────────────┴────────────┐
                  │                         │
             A：通常条件               B：代替条件
       気圧高度15km以上を          気圧高度が60秒以上更新停止
       連続30回取得                AND LOW確認から1時間以上
                                  AND GPS高度10km以上
                                      ＋GPS受信・UT更新の確認
                  │                         │
                  └──────── どちらか成立 ────┘
                               │
                     警告シーケンス開始
                               │ 最短66秒
                              通電
```

**Aが成立すれば1時間待つ必要はありません。Bは3条件が同時に揃う必要があります。**

## 2. 開始条件を詳しく知る

### 2.1 フライトピン：HIGHを見てからLOWへ

| ピンの状態 | ソフトウェアでの意味 |
|---|---|
| 挿入：HIGH（1） | 開始させない。開始前なら高度の回数と待ち時間をリセット |
| 抜去：LOW（0） | HIGHを一度認識済みなら、高度・時間の監視を開始 |
| 起動時からLOWのまま | HIGHを認識していないので、開始しない |

ピンのテレメトリ`Fp`は現在1Hzです。**1時間の起点は物理的に抜いた瞬間ではなく、MainがLOWを認識して監視を開始した時刻**です。通常の周期差に加え、タスク遅延によって認識が遅れることがあります。

FlightPinが送る`ET`はピン状態の継続時間ですが、IGNの1時間タイマーは`ET`を使っていません。無効な`Fp`を受信すると開始判定をリセットするため、`ET`とIGNの待ち時間が一致しない場合もあります。

### 2.2 A：気圧高度15km以上を連続30回

- `PA >= 15000`の有効な新規測定を30回数えます。15,000mちょうども含みます。
- 1Hzならおおむね30秒ですが、判定は**時間ではなく回数**です。
- 14,999m以下や、対象の気圧パケットの無効測定を受け取ると0回に戻ります。
- ピン挿入中や抜去直後に溜まっていたデータは使いません。
- 同じ測定時刻`Ts`の再送は、回数を増やしません。
- **無受信の時間だけでは回数をリセットしません。** 例えば29回の後で通信・処理が途切れ、その後に新しい有効な15km以上の測定を受け取ると30回になります。「途切れない30秒間」の保証ではありません。

使用するのはIGN自身の気圧高度です。MissionBus側にも気圧計がありますが、送信元フィールド`Sm`で区別し、そちらの測定では回数や更新時刻を進めません。

### 2.3 B：気圧更新停止＋1時間＋GPS高度10km以上

| 条件 | 実際に確認すること |
|---|---|
| 気圧更新停止 | 最後の有効なIGN気圧高度から60,000ms以上経過 |
| 時間到達 | MainがLOWを確認してから3,600,000ms以上経過 |
| GPS高度 | MissionBusの`AL`が整数で10,000m以上、かつ後述の受信確認を満たす |

一度も有効な気圧高度を取得していなければ、LOW確認時刻から60秒を数えます。無効な気圧パケットが届き続けても「有効測定の最終時刻」は進みません。

**高度の数値が同じでも、新しい有効な測定が届けば更新です。** 例えば気圧高度が毎秒9,000mであっても、測定時刻が進んでいれば更新停止にはなりません。

有効な気圧測定が再開すると、Bの更新停止条件は不成立に戻ります。ただし、すでにシーケンスに入った後は、それを理由に中止しません。

### 2.4 GPSには「10km以上」以外の確認もある

既存MissionBusの`AL`（整数m）と`UT`（`YYYY-MM-DD hh:mm:ss.cc`）を使います。

- `UT`の形式・日付・時刻を検査します。日付が未設定の初期値などは使いません。
- 前回より`UT`が進んだ受信だけを新しいデータとして扱います。
- 同じ`UT`や過去の`UT`を受信しても、受信時計を延長しません。
- 新しい受信からの経過とMain内のキュー待ち時間の見積もりを合わせ、**5秒未満**の場合だけ採用します。5秒ちょうどは不成立です。
- GPSには連続30回という条件はありません。Bのほかの条件が揃っていれば、採用可能な10km以上のGPSデータ1回で成立し得ます。

**ここで確認できるのは、パケットの形式・GPS時刻の進行・受信の新しさです。GPS高度そのものの測定成功や測定時刻までは確認できません。** 時刻だけ進み、高度だけが古いまま再送される故障は検出できません。CAN転送自体の遅延もこの5秒には直接含めていません。

### 2.5 具体例

| LOW確認後の状況 | シーケンス開始？ | 理由 |
|---|---|---|
| 10分後、15km以上を連続30回 | 開始する | A成立。GPSも1時間待ちも不要 |
| 59分後、気圧更新が2分停止、GPSは12km | 開始しない | Bの1時間が未到達 |
| 1時間後、気圧9kmを正常に毎秒取得、GPSは12km | 開始しない | A未成立、Bの更新停止も未成立 |
| 1時間後、気圧更新停止が59秒、GPSは12km | まだ開始しない | 60秒以上の停止が必要 |
| 1時間後、気圧更新が2分停止、採用可能なGPSが10km | 開始する | Bの全条件が成立 |
| 1時間後、気圧更新停止、GPSは9,999m | 開始しない | GPS高度不足 |
| 1時間後、気圧更新停止、GPSは12kmだがUTが5秒以上停止 | 開始しない | GPS受信確認を満たさない |
| 1時間時点で条件不足、1時間5分後に全条件が揃う | その時点で開始 | 1時間到達の瞬間だけを判定するわけではない |
| 途中で再挿入し、その後抜き直す（開始要求前） | 判定を最初からやり直す | 回数・待ち時間・測定状態をリセット |

## 3. 開始してから終了するまで

以下の時刻は、**シーケンス開始を0秒**とした最短の目安です。LOW確認からの1時間とは別です。

| 経過 | 状態名／`Ph` | HIGH側出力 | LOW側出力 | 表示・動作 |
|---|---|---|---|---|
| 開始前 | `Disarmed`／5 | LOW | LOW | 待機。NORMAL LED消灯 |
| 0～1秒 | `Startup`／0 | HIGH | LOW | 開始警告。ブザー連続、NORMAL LED点灯 |
| 1～61秒 | `Countdown`／1 | 断続 | LOW | 1秒ごとに0.2秒のブザー、LEDも同期 |
| 61～66秒 | `Final`／2 | HIGH | LOW | 最終警告。ブザー連続、LEDは5Hz点滅 |
| 66秒～ | `Ignition`／3 | HIGH | HIGH | 点火出力を有効化、LED点灯。通電時間設定は60秒 |
| 通電終了後 | `Done`／4 | LOW | LOW | 2秒ごとに0.1秒だけLED点灯 |

正常に進行すれば、開始からおおむね126秒で終了します。タスクが遅れると警告時間は延びます。警告段階を飛ばして通電する設計ではありません。

通電停止は、状態機械の60秒判定と、別の高優先度タスクによる60秒待ちの両方で行います。後者は同じマイコン内のソフトウェアであり、独立したハードウェア遮断器ではありません。実際の通電時間・停止遅延は実機測定が必要です。

> 出力名の「HIGH側」「LOW側」と、信号レベルのHIGH/LOWは別です。LOW側出力も、通電時には信号レベルHIGHになります。

## 4. 条件はどこで変える？

### 4.1 よく変更する高度と待ち時間

編集場所：`src/modules/IGN/main.cpp`の先頭付近。

```cpp
constexpr int32_t ignition_altitude_m = 15000; // 気圧高度の下限、m
constexpr uint32_t ignition_fallback_delay_ms = 60UL * 60UL * 1000UL; // LOW確認から1時間
```

時間はミリ秒です。`1000ms = 1秒`なので、30分にする場合は`30UL * 60UL * 1000UL`です。
この待ち時間を変えても、Aの「気圧高度を連続30回」という条件や、開始後のカウントダウン時間は変わりません。

### 4.2 設定一覧

以下はソースを変更して再ビルド・再書き込みする設定です。地上から変更するコマンドは、今回の開始条件用には実装されていません。

| 変えたいもの | ファイル（`src/`以下） | 定数 | 対象版の値 |
|---|---|---|---|
| 通常条件の気圧高度 | `modules/IGN/main.cpp` | `ignition_altitude_m` | `15000` m |
| LOW確認後の代替条件待ち時間 | 同上 | `ignition_fallback_delay_ms` | `3600000` ms |
| 高度を連続取得する回数 | `components/IGN/IGNAltitudeGate.h` | `required_samples` | `30` 回 |
| 気圧更新停止とみなす時間 | `components/IGN/IGNStartGate.h` | `pressure_timeout_ms` | `60000` ms |
| 代替条件のGPS高度 | 同上 | `gps_min_altitude_m` | `10000` m |
| GPS受信の採用期限 | 同上 | `gps_max_age_ms` | `5000` ms未満 |
| 最初の連続警告 | `components/IGN/IGNSequence.h` | `startup_buzz_ms` | `1000` ms |
| 間欠ブザーのカウントダウン | 同上 | `countdown_ms` | `60000` ms |
| 最終連続警告 | 同上 | `final_buzz_ms` | `5000` ms |
| 通電時間 | 同上 | `ignition_ms` | `60000` ms |

「待ち時間1時間」「気圧更新停止60秒」「警告中のカウントダウン60秒」「通電60秒」は、すべて別の設定です。

値を変えたら、境界値のテストも更新してください。`required_samples`には1以上を設定します。0にすると、回数0の初期状態が成立状態になってしまいます。

### 4.3 接続に関係する設定

`src/modules/IGN/main.cpp`の対象版では次の設定です。実基板の配線と一致しているかを確認します。

| 項目 | 値 |
|---|---|
| IGN module ID | `'I'`＝`0x49` |
| unit ID | `0x62`。MissionBusから受けるGPSも同じunit IDを購読 |
| NORMAL LED | GPIO 6 |
| HIGH側出力 | GPIO 4 |
| LOW側出力 | GPIO 5 |
| FlightPin入力 | GPIO 21 |
| CAN | RX 44、TX 43 |
| I2C | SDA 17、SCL 16 |

気圧高度`PA`は設定された基準気圧を使う計算値、GPS高度`AL`はGPSライブラリの値です。両者を同じ基準へ補正する処理はありません。「発射地点からの高さ」と思い込まず、運用する高度基準・基準気圧を別途確認してください。

## 5. いつアボートされる？

### 5.1 リセット・アボート・正常終了の違い

| 発生すること | 動作 | その後 |
|---|---|---|
| 開始要求前にピンを再挿入 | 高度回数・タイマー・GPS状態をリセット | 抜き直すと再び判定できる |
| 開始要求後～通電中にピンがLOW→HIGH | GPIO割り込みで出力停止を要求し、両出力をLOWへ落とす | 状態処理が進むと`Disarmed`。通常のMainからの再開始はしない |
| 開始要求直後のピン再確認でHIGH | `abortSequence()`を呼び出し、出力停止 | 同上 |
| ソフトウェアから`abortSequence()`を呼ぶ | 出力停止と中止要求 | 通常運用のCAN中止コマンドとしては実装されていない |
| 通電時間設定の60秒に到達 | 出力停止、`Done`へ | 正常終了。アボートではない |
| 初期化や通電監視の準備に失敗 | 出力を停止したまま、開始不可または`Fault` | 起動失敗の場所によっては状態通知自体が出ない |

割り込みは`Startup`・`Countdown`・`Final`・`Ignition`と開始予約時に有効です。待機中のピン挿入は、通常ループによる判定リセットとして扱います。

出力停止を先に行い、ログや`Ph`の更新は後になります。**アボートで止まるのは電気的な出力です。すでに点火したものの燃焼を取り消す機能ではありません。**

### 5.2 自動アボートされないこと

**開始条件は「シーケンスに入るための条件」であり、「通電まで維持し続ける条件」ではありません。**

開始後に次が起きても、現コードはそれだけではアボートしません。

- 気圧高度が15km未満になる。
- GPS高度が10km未満になる。
- 気圧計が復旧し、代替条件が不成立になる。
- GPS、CAN、気圧データの更新が止まる。
- INA226の電流・電圧測定が異常になる。
- SDカード記録や地上へのテレメトリが止まる。
- 不正な`Fp`パケットを受信する。開始判定はリセットされますが、すでに進行中のシーケンスを止める呼び出しはありません。

開始後のピン中止は、実GPIOのLOW→HIGH割り込みが重要です。正常な`Fp=1`パケットを受信するだけで進行中のシーケンスを止める設計ではありません。

### 5.3 アボート後に抜き直したら？

通常のIGNモジュールでは再開始しません。

- Mainは開始要求を出す時点で`ignition_start_requested_`を立て、その起動中には戻しません。開始要求が拒否された場合も自動再試行しません。
- シーケンス側も、一度開始したら`has_started_`により再開始を拒否します。
- `Disarmed`表示だけでは「一度も開始していない待機」と「中止後」を区別できません。

これらの記憶は再起動で失われます。再起動すると新しい起動として扱われますが、改めてHIGH→LOWの認識が必要です。原因未確認の再起動を、単なる再試行操作として扱わないでください。

## 6. 基本的な使い方と確認の順序

### 6.1 準備

1. 使用する作業コピーに、対象版の`src/modules/IGN/main.cpp`とPlatformIOの`[env:IGN]`があることを確認する。
2. 4章の設定を確認する。特に、高度の単位、1時間の起点、通電時間60秒を確認する。
3. 最初の動作確認は、イグナイタと点火用電源を切り離した状態で行う。実GPIOの波形と状態表示を確認する。
4. 代替条件を使う場合は、MissionBusから既存GPSパケットがCAN経由で届くことを確認する。MissionBusの書き換えは不要。

対象作業コピーでのビルド：

```powershell
platformio run -e IGN
```

書き込む基板を特定してから、通常のPlatformIO書き込み手順を実施します。この資料作成では、実機への書き込みや出力操作は行っていません。

### 6.2 起動から待機へ

1. フライトピンを挿入した状態で起動する。
2. `Fp=1`が実際に受信されるまで待つ。起動直後にすぐ抜くと、HIGHを認識し損ねる可能性がある。
3. `Ph=5`、`Ig=0`、出力LOWを確認する。通信がない場合は、起動成功とみなさず9章を確認する。
4. ピンを抜くと、MainのLOW確認時点から回数・時間の監視が始まる。
5. AまたはBが成立すると`Ph=0`へ移る。ピン抜去だけではシーケンスに入らない。

地上の通常高度ではAもGPSの10km条件も成立しないため、ピンを抜いて1時間待つだけでは動作確認になりません。

### 6.3 条件を模擬して確認する

実出力を負荷から切り離し、下記をホストテストや制御された測定入力で確認します。
`begin(true)`や`startSequence()`の直接呼び出しは、Mainの高度・時間判定を通らないため、開始条件の試験の代わりにはなりません。

| 確認項目 | 期待する結果 |
|---|---|
| 起動時からLOWのまま | 開始しない |
| HIGH認識後、15,000mを29回／30回 | 29回では待機、30回で開始 |
| 途中で14,999mまたは無効測定 | 回数をリセット |
| 同じ`Ts`の気圧を繰り返す | 回数を増やさない |
| 気圧停止59,999ms／60,000ms | 後者から更新停止と判定 |
| 待ち時間3,599,999ms／3,600,000ms | 後者からBの時間条件成立 |
| GPS 9,999m／10,000m | 後者から高度条件成立 |
| GPSのUTが同じまま再送される | 受信期限を延長しない |
| 開始前の再挿入 | 回数と待ち時間をリセット |
| 各警告段階・通電中の再挿入 | 出力停止。再度抜いても通常のMainは再開始しない |
| 通電時間に到達 | 出力停止、`Done` |

時間を短くした試験版を使った場合は、運用版の設定へ戻し、実際に書き込むバイナリがどの設定で作られたか記録します。

## 7. 状態の見方

### 7.1 テレメトリ

| 種類 | 主な識別子 | 見る項目 |
|---|---|---|
| FlightPin | component `0x50`、packet `'F'` | `Fp`＝1/0、`ET`＝状態継続ms、`TS`＝時刻 |
| IGN自身の気圧 | component `0x25`、packet `'E'`、`Sm=0x49` | `PA`＝高度m、`Va=1`＝有効、`Ts`＝測定時刻 |
| MissionBusのGPS | component `21`＝`0x15`、packet `'M'`、unit `0x62` | `AL`＝高度m、`UT`＝GPS時刻 |
| IGNの状態 | component `36`＝`0x24`、packet `'S'` | 下表 |
| IGNの電力 | component `36`＝`0x24`、packet `'I'` | `Vi`＝mV、`Ii`＝mA、`Pi`＝mW |

| 状態フィールド | 意味・注意点 |
|---|---|
| `Ph` | 状態番号。0～6の対応は3章と5章を参照。6は`Fault` |
| `Et` | 現在の段階に入ってからの経過ms |
| `St` | シーケンス開始からの経過ms。LOW確認からの1時間ではない |
| `Rt` | 警告段階での通電までの残りms。待機中の1時間残量ではない |
| `Hi` / `Lo` / `Ig` | ソフトウェアが保持する出力状態。実電流や実際の点火成功の証明ではない |
| `Ok` | IGN初期化完了かつ状態が`Fault`でないこと。気圧・GPS・配線全体の健全性ではない |

状態は変化時と約1秒周期で送信します。電力測定は待機中1Hz、シーケンス開始後10Hzへ変更され、Doneへ移行すると測定・送信を1Hzへ戻します。

**高度の現在の連続回数、1時間タイマー残量、最後の有効気圧からの時間、A/Bのどちらで開始したかは専用テレメトリになっていません。** 開始前の`Rt=0`を「すぐ通電する」の意味で読まないでください。

### 7.2 ログ

- `Flight pin removed and ignition start conditions met; sequence requested`：開始要求を受理。
- `Flight pin and ignition start conditions met; sequence request rejected`：開始要求が拒否された。
- `IGN phase: Startup`など：状態が変わった。
- `Flight pin inserted during ignition sequence start; aborted`：開始直後のピン再確認で中止。

ピン割り込み自体はログを書きません。上記の`aborted`ログがないことは、アボートしていない証明にはなりません。

## 8. 想定する不具合・故障モード

以下は、コードから分かる処理と、それに基づく故障時の予測です。実機で発生を確認した不具合一覧ではありません。

### 8.1 センサ・通信

| 故障・状態 | 開始前の予測動作 | 検出できないこと／影響 |
|---|---|---|
| 気圧計が初期化できない | 有効高度が届かない。LOW確認から60秒で更新停止扱い | 1時間とGPS条件も揃えばBで開始し得る |
| 気圧読み取りが無効値になる | `Va=0`等で回数リセット。有効更新時刻は進まない | 故障だけで即開始はしない。Bの全条件が必要 |
| 気圧計が低い固定値を返し、`Ts`だけ進む | 更新が続くためBにならず、Aも成立しない | 値の固着そのものの故障検出はない |
| 気圧計が15km以上の誤った固定値を返す | 有効扱いの新規測定が30回続くとA成立 | GPSによる照合はAにはない |
| 基準気圧が誤設定 | `PA`の値がずれ、開始が早まる／遅れる可能性 | 現実の高度との一致はコードだけでは保証しない |
| GPS・CAN受信が途絶 | GPS受信期限でB不成立 | Aが成立すればGPSなしでも開始する |
| GPSのUTが止まる | 同じUTでは期限を延長しない | 時刻だけ進み高度だけ古い故障は検出不可 |
| GPSが単発で10km以上の誤値を出す | 他のB条件が揃えば開始し得る | GPSの連続回数条件・測位品質判定はない |
| GPSの時刻が過去へ戻る | 前回より進むUTになるまで新規受信と認めない | GPSが動いていてもBが成立しない場合がある |
| 別モジュールが同じunit/componentのGPSを送る | そのパケットも購読対象になる | 既存GPS形式にはmodule IDがなく、MissionBusだけの送信という構成が前提 |
| 受信キューが溢れる／Mainが遅れる | 気圧の計数が遅れる、GPSが期限切れになる等 | 欠落した低高度測定を見逃す可能性があり、「全測定が連続30回」の保証ではない |
| 更新停止がセンサでなく処理系の不調に由来する | 有効気圧が届かなければ同じ更新停止扱い | 60秒停止は「気圧計故障の確定診断」ではない |

気圧高度の計算式や入力範囲を用意していることと、使用するセンサがその高度・温度・圧力で正確に測れることは別です。実センサの仕様・校正と飛行相当環境での確認は、本コード確認には含まれません。

### 8.2 ピン・電源・制御回路

| 故障・状態 | 予測動作・注意点 |
|---|---|
| ピン入力がHIGHに張り付く | 抜去を認めず、開始しない |
| ピン入力が起動時からLOWに張り付く | HIGHを認識できず、開始しない |
| HIGH認識後にLOWへ張り付く | 抜去扱いで判定が進む。再挿入してもHIGHへ変わらなければアボートできない |
| 接点のチャタリング・ノイズ | 開始前はリセット、開始後は一瞬のHIGHでもアボートする可能性。ソフトウェアのデバウンスはない |
| ピン入力が浮く | 不定のHIGH/LOWになる可能性。設定は`INPUT`で、内部プルアップ／プルダウンを有効化していない |
| 待機中の非常に短い再挿入 | Mainや1Hzのサンプルが見逃すとタイマーをリセットしない可能性。開始前のISRは中止処理をしない |
| INA226が起動時に接続・校正失敗 | IGN初期化失敗、開始しない。タスク起動前なら`Fault`のLEDや通知も出ない場合がある |
| INA226が開始後に故障／電流異常 | 電流値による自動アボートはない。値が見えていることと保護機能があることは別 |
| イグナイタ断線・点火電源不足 | GPIOが通電状態でも実際には点火しない可能性。点火成功・不成功の自動判定はない |
| 出力スイッチの短絡・固着 | GPIOをLOWへしても実電流が止まらない可能性。ソフトウェアだけでは遮断を保証できない |
| 通常のIGN処理だけが遅延 | 警告が延びる。通電中は別タスクも停止を試みる |
| CPU全体停止・スケジューラ停止・長い割り込み禁止 | 別タスクやGPIO割り込みも動作できない可能性。独立ハードウェア保護ではない |
| 電源断・リセット | 状態、回数、タイマー、一度だけ開始する記憶が失われる。再起動中の実出力状態は回路側も確認が必要 |
| GPIO番号設定の誤り | 負値・重複等は検査するが、実配線との一致までは検査しない。設定エラーの全種類を安全に検出するわけではない |

### 8.3 起動・記録・状態表示

| 状態 | 予測動作・注意点 |
|---|---|
| カーネル・I2C・割り込み登録が失敗 | `setup()`が途中で戻り、Mainの開始判定が始まらない。常に`Ph=6`を通知するわけではない |
| 既にGPIO ISRサービスが登録されている | 対象版の登録処理は失敗として扱うため、開始判定を起動しない |
| Main／FlightPinのタスク作成失敗 | それらの`begin()`の戻り値をMainの初期化コードで検査していない。起動表示と実動作が一致しない可能性 |
| Logger・SDカード・地上通信が故障 | 記録・表示できなくても点火制御が動き続ける可能性。記録成功を開始条件にしていない |
| `Fault`表示がない | 正常とは限らない。初期化途中の失敗で表示タスクまで起動しない場合がある |
| `Disarmed`表示になった | 初期待機か、中止後かを表示値だけでは区別できない |
| 開始要求が拒否された | Mainの開始要求済みフラグは残り、同じ起動中は自動再試行しない |

## 9. 「始まらない」ときの確認順

1. **対象のファームウェアか？** IGN環境と設定値、module ID、unit IDを確認する。
2. **初期化が最後まで進んだか？** 電源、I2C、INA226、GPIO割り込み登録、Main／FlightPinタスクを確認する。
3. **HIGHを一度認識したか？** 起動時からLOWのままでは開始しない。
4. **現在もGPIOがLOWか？** テレメトリだけでなく、実ピンの状態・ノイズを確認する。
5. **すでに一度、開始要求を出していないか？** 中止後や要求拒否後は、条件が揃っても通常のMainは再試行しない。
6. **Aを期待する場合：** IGN自身の`Sm`、`Va`、`PA`、`Ts`を確認する。途中の低高度・無効測定で回数が戻っていないかを見る。
7. **Bを期待する場合：** 有効な気圧が本当に60秒止まったか、LOW確認から1時間経過したか、GPSの`AL`と`UT`が採用可能かを別々に確認する。
8. **すでに警告中ではないか？** シーケンスに入っても、通電までは最短66秒待つ。

不成立の理由を1つの状態フィールドで表示する機能はありません。生の測定・ピン・状態ログを合わせて判断します。
