# ESP32-S3向けTracker LoRa受信プログラム

作業者：Codex

## 目標

`src/modules/Tracker/main.cpp`から送信されたLoRaテレメトリを、
`src/modules/LoRa_ESP/main.cpp`で受信してPCへWCPP形式で転送する。
受信専用とし、PCからの`'s'`コマンドによる無線送信処理は持たない。
E220ドライバとWOBCのパケット・USBシリアルバスは共通コードを利用する。

起動処理（`setup()` / `loop()`）、GPIO・チャンネル設定、受信タスクは
`src/modules/LoRa_ESP/main.cpp`に配置する。
共通E220ドライバは`src/components/LoRa/e220.h`と`e220.cpp`を参照する。

## 基板とピン

GPIOは`hardware/modules/LoRa2026/LoRa_ESP-backups/LoRa_ESP-2026-08-28_173013.zip`
内の`LoRa_ESP.kicad_pcb`で確認した。
初期設定では元の`src/modules/LoRa/main.cpp`と同じく2台目のE220を使う。
異なる基板を使う場合は`main.cpp`冒頭の定義を実配線に合わせる。

| ESP32-S3側の信号 | LoRa2 / U401（初期設定） | LoRa1 / U301 |
| --- | --- | --- |
| TX → E220 RXD | GPIO7 | GPIO13 |
| RX ← E220 TXD | GPIO18 | GPIO12 |
| AUX | GPIO8 | GPIO11 |
| M0 | GPIO5 | GPIO14 |
| M1 | GPIO6 | GPIO21 |
| アンテナV1 | GPIO9 | GPIO39 |
| アンテナV2 | GPIO10 | GPIO40 |

アンテナはV1=HIGH、V2=LOW。ステータスLEDはGPIO42、エラーLEDはGPIO41。
UART1を1台のE220に割り当てる構成であり、2台の同時制御は行わない。

## 通信設定と使い方

- モジュールID：`0x4C`、LoRaコンポーネントID：`0x10`。
- 無線：チャンネル`3`、SF9、帯域幅125kHz、透過モード、アドレス`0xFFFF`。
- E220設定時のUART：9600bps。通常時：115200bps、8N1。
- USBシリアル：115200bps設定、WOBCのバイナリパケット形式。
  PC側の既存WCPP対応ソフトで受信機のCOMポートを開く。
  通常のシリアルモニターでは数値を文字として表示できない。
- CANは元のLoRa mainと同じく初期設定では無効。
  使用時は`LORA_USE_CAN=1`にする。CAN RX=GPIO44、TX=GPIO43、125kbps。

Trackerのチャンネル`3`・SF9・帯域幅125kHz・透過モード・アドレス`0xFFFF`と一致する。
チャンネルは相手と一致させる必要がある。
`src/modules/MissionBus/main.cpp`はチャンネル`11`なので、その機体と通信する場合は
このmainの`LORA_CHANNEL`も`11`に変更する。

無線フレームは既存と同じ`[長さ][WCPPパケット][CRC8]`。
受信時にはE220が付加したRSSIを読み取り、CRC・長さ・ヘッダー長を検証してから
`Ss`エントリを付加し、WOBCバスへ転送する。
元のパケットID・コンポーネントID・送信元・宛先・シーケンス・ペイロードを保持する。
USB出力は`[Ss追加後のWCPPパケット][再計算したCRC8][0x00]`。
初期化ログ・エラー・受信機自身のハートビートも既存のWCPP形式で出力する。
バイナリ転送に`Serial.print()`の文字列を混在させない。

Trackerは現在、次のテレメトリをそれぞれ既定で1秒ごとに送信する。
送信元ユニットIDは`0x61`、宛先は`0xFF`。

| データ | パケットID / コンポーネントID | エントリ（送信コードでの表記） |
| --- | --- | --- |
| GPS | `'M'` / `0x15` | `LA`: 緯度、`LO`: 経度、`AL`: 高度[m] |
| 気圧 | `'E'` / `0x25` | `Sp`: 基準気圧[Pa]、`PR`: 気圧[Pa]、`TE`: 温度[℃]、`HU`: 湿度[%]、`PA`: 気圧高度[m]、`Ts`: 起動後時間[ms] |

WCPPのエントリ名は大文字・小文字を区別するビットを持たず、
PC側のデコーダーでは`LA`が`La`、`PR`が`Pr`などと表示される場合がある。
受信側ではエントリ名の変換を行わない。
Trackerは`Im`を持つパケットを送信対象から除外するため、電源テレメトリと
Tracker自身のハートビートは現在の送信プログラムでは無線に流れない。
ローカル形式の診断パケットも受信できるよう、受信側では送信元IDによる除外はしない。

長さフィールドの制約により、無線に載せられるWCPPパケットは最大254バイト。
受信はRSSI用に最大4バイトを追加するため、元のWCPPパケットが251バイトを超えると破棄する。
この上限はソフトウェア上のフレーム制約であり、長いフレームの実機通信は別途確認が必要。
初期化失敗時はエラーLEDを点灯状態に保ち、無線処理タスクを起動しない。

## 共通ドライバの修正

- 8バイトの初期設定に必要な11バイトのコマンド領域を確保し、引数長を検査。
- 1バイトの長さフィールドに収まらない送信を拒否。
- 設定レジスタの読み書き失敗を呼び出し元へ返す。
- 受信完了・破棄後に受信待ち状態を解除し、同じ長さのパケットも再受信可能にする。
- AUX待機に`delay(1)`を入れ、ESP32-S3で他タスクが動作できるようにする。
- Tracker側で使う`lora.h`のメンバー宣言順をUART → E220に修正し、
  E220の参照先を先に構築する。

## ビルドと検証

```sh
pio run -e LoRa_ESP
```

受信機への書き込み：

```sh
pio run -e LoRa_ESP -t upload
```

受信機に書き込んでPC側ソフトからCOMポートを開き、Trackerを起動する。
GPS・気圧のパケットと受信強度`Ss`を確認する。
初期設定のピン割り当ては上表のLoRa2 / U401用。

PlatformIOの`LoRa_ESP`環境は`esp32-s3-devkitc-1`を使用し、
このmain、E220ドライバ、必要なWOBCライブラリだけをビルドする。

受信専用化とUART宣言順の修正後、`pio run -e LoRa_ESP -e Tracker`は両環境で成功した。
`.pio/build/LoRa_ESP/firmware.bin`と`.pio/build/Tracker/firmware.bin`を生成した。
既存の共通コード・ビルド設定・CAN依存ライブラリの警告は残っている。

既存のE220モック回帰テスト7件は`src/library/test/test_e220`に配置。
移植時のESP32-S3コンパイラによる`-Wall -Wextra -Werror -fsyntax-only`構文確認は成功。
このPCにホスト用C++コンパイラがないため、モックテストの実行は未確認。
実機での書き込み・無線通信・RSSI・アンテナ切替・CAN接続は未検証。

UART APIの参照：[Espressif Arduino-ESP32 Serial API](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/serial.html)。
