# Separationモジュールの使い方

更新日：2026-09-17。対象は、気圧開始条件と開始予約中のアボート競合を修正したSeparation／Nichrome実装です。未コミットの変更を含みます。

「シーケンス開始」は警告音とカウントダウンの開始、「通電開始」はニクロム線用の両出力を有効にする時点です。両者は36秒以上離れています。

## 1. 動作の全体像

1. FlightPin挿入中のHIGHを、起動後に一度認識する。
2. 抜去中のLOWを認識し、実GPIOもLOWであることを確認して気圧監視と代替タイマーを開始する。
3. 気圧高度20,000 m超の有効な新規測定を連続30回取得するか、抜去確認から1時間経過し有効な気圧更新が60秒停止したら、一度だけシーケンス開始を要求する。
4. 開始警告1秒、カウントダウン30秒、最終警告5秒を経て通電する。
5. 通電時間の設定は120秒。終了すると出力を停止して`Done`になる。
6. 開始要求後にピンを再挿入すると、割り込みで出力を停止する。同じ起動中には再開始しない。

```text
起動 → 挿入HIGHを認識 → 抜去LOWを認識＋実GPIO LOW
                                     │
                       気圧高度20 km超を連続30回
                        OR（抜去後1時間＋気圧更新停止60秒）
                                     │
                             シーケンス開始
                                     │
                 開始警告1秒 → カウントダウン30秒 → 最終警告5秒
                                                               │
                                                          通電120秒
                                                               │
                                                             Done
```

**起動時からピンが抜けているだけでは開始しません。** GPS高度は条件に使いません。正常な気圧更新が続く限り、1時間経過だけでは開始しません。気圧を一度も取得できない場合は抜去確認を更新停止時間の起点にします。

高度判定は20,000 mちょうどを含みません。無効値・閾値以下で回数をリセットし、抜去前の測定・古い測定・重複時刻を採用しません。ただし、IGNと同様、無受信の時間だけでは回数をリセットしません。連続30回は厳密な連続30秒の保証ではなく、値の固着も判定しません。これらは今回の修正対象外です。

## 2. FlightPinとタイマー

| 状況 | 開始前の動作 |
| --- | --- |
| `Fp=1`（挿入）を受信 | 挿入確認を記憶し、抜去判定とタイマーをリセット |
| 挿入確認後に`Fp=0`（抜去）を受信 | 実GPIOがLOWならMainがタイマーを開始 |
| 起動後に一度も`Fp=1`を受信していない | 開始しない |
| 待機中に`Fp=1`を受信 | 待ち時間と高度回数を破棄。抜き直した後に判定を最初からやり直す |
| `Fp`欠損・整数以外・0/1以外 | 抜去判定とタイマーをリセット。過去の挿入確認は保持 |
| 実GPIOがHIGH | タイマーをリセットし、開始しない |

FlightPinテレメトリは1 Hzです。1時間の起点は物理的に抜いた瞬間ではなく、**Mainが抜去と実GPIO LOWを確認して計測を開始した時刻**です。周期差やタスク遅延により認識が遅れることがあります。

`Fp=0`を毎秒受信してもタイマーはリセットされません。無効データの後は、新しい有効な`Fp=0`を受け、実GPIOもLOWなら計測をやり直します。挿入パケットと抜去パケットが同じ処理回に届いた場合も、以前のタイマーは破棄します。

実GPIOだけでHIGHを検出した場合は計測を止めますが、記憶している抜去判定は消しません。最後の有効パケットが抜去であれば、実GPIOがLOWに戻った時点から再計測します。

現在、`Fp`の無受信タイムアウトや受信時刻の鮮度検査はありません。最後の有効状態が抜去で、実GPIOもLOWなら、新しいパケットが届かなくてもタイマーは進みます。FlightPinの`ET`・`TS`も開始判定には使っていません。

## 3. 時間とブザー・LED

以下は**開始条件成立後のシーケンス開始を0秒**とした、正常進行時の最短目安です。抜去後の高度監視・代替タイマーとは別です。

| 経過 | 状態／`Ph` | HIGH側の信号 | LOW側の信号 | 動作 |
| --- | --- | --- | --- | --- |
| 開始前 | `Disarmed`／5 | LOW | LOW | 条件待ち。NORMAL LED消灯 |
| 0～1秒 | `Startup`／0 | HIGH | LOW | ブザー連続、LED点灯 |
| 1～31秒 | `Countdown`／1 | 断続 | LOW | 1秒ごとに0.2秒のブザー、LED同期 |
| 31～36秒 | `Final`／2 | HIGH | LOW | ブザー連続、LEDは5 Hz点滅 |
| 36～156秒 | `Ignition`／3 | HIGH | HIGH | ニクロム線用出力を有効化、LED点灯 |
| 終了後 | `Done`／4 | LOW | LOW | 2秒ごとに0.1秒のLED点灯 |
| 異常時 | `Fault`／6 | LOW | LOW | 動作中の状態表示処理ではLEDが2 Hz点滅 |

クラス内では分離の通電段階も`Ignition`という名前を使用しています。「LOW側出力」という名前と、信号レベルLOWは別です。通電時は両側とも信号レベルHIGHです。

タスクが遅れた場合、警告時間は延びます。遅れた分の警告段階を飛ばして通電する実装ではありません。120秒の停止判定は状態機械と別の高優先度タスクで行いますが、同じマイコン内の処理です。実際の遮断遅延は実機での確認が必要です。

## 4. アボートと再開始

| 操作・事象 | 結果 | 抜き直して再開始できるか |
| --- | --- | --- |
| 開始要求前の再挿入 | 開始待ち時間・高度回数をリセット | できる。開始条件を再び満たす必要がある |
| 開始要求後、警告中・通電中の再挿入 | GPIOのLOW→HIGH割り込みで出力を停止 | できない |
| 開始要求直後のGPIO再確認でHIGH | `abortSequence()`で停止 | できない |
| 通電時間120秒に到達 | 正常終了、`Done`へ | できない |
| 開始要求が拒否される | Mainはその起動中に再試行しない | できない |

アボートは出力停止を先に実行し、`Disarmed`への状態遷移やテレメトリ更新はNichromeタスクで後から行います。`Disarmed`だけでは、初回待機中と中止後を区別できません。再起動すると開始履歴は消え、再び挿入HIGH→抜去LOWの認識が必要になります。

有効な`Fp=1`パケットだけを受け取っても、進行中のシーケンスを止める呼び出しはありません。開始後の再挿入による停止は**実GPIOの立ち上がり割り込み**と開始要求直後の実GPIO確認で行います。チャタリングを除外するデバウンスはなく、有効期間中の立ち上がりは中止として扱います。

気圧・GPSの異常、FlightPinパケットの無効値や無受信、電流測定の異常、SD記録停止を理由とする自動アボートは実装されていません。通信経由の開始・中止・時間変更コマンドもありません。

## 5. 設定を変更する

設定はソースを編集し、再ビルド・再書き込みして反映します。

| 設定 | ファイル | 定数 | 現在値 |
| --- | --- | --- | --- |
| 気圧高度の閾値（超過でカウント） | `src/modules/Separation/main.cpp` | `separation_altitude_m` | 20,000 m |
| 抜去確認からの代替開始待ち | 同上 | `separation_fallback_delay_ms` | 3,600,000 ms |
| 有効な気圧更新の停止時間 | `src/components/Nichrome/NichromeStartGate.h` | `pressure_timeout_ms` | 60,000 ms |
| 高度条件の連続回数 | 同上 | `required_samples` | 30回 |
| 開始警告 | `src/components/Nichrome/NichromeSequence.h` | `startup_buzz_ms` | 1,000 ms |
| カウントダウン | 同上 | `countdown_ms` | 30,000 ms |
| 最終警告 | 同上 | `final_buzz_ms` | 5,000 ms |
| 通電・遮断タスク待ち時間 | 同上 | `ignition_ms` | 120,000 ms |

例えば開始待ちを2分にする場合：

```cpp
constexpr uint32_t separation_fallback_delay_ms = 2UL * 60UL * 1000UL;
```

この変更では警告36秒や通電120秒は変わりません。代替待ち時間を0にしても挿入・抜去確認と気圧更新停止60秒は必要です。高度条件は代替待ち時間に依存しません。時間設定を変えたらコメントと関連テストも合わせて更新します。

## 6. ビルド・書き込み・動作確認

プロジェクトのルートで実行します。

```powershell
pio run -e Separation
pio run -e Separation -t upload
pio device monitor -b 115200
```

`pio`にPATHが通っていないWindows環境では、例えば次のように実行します。

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run -e Separation
```

ソフトウェアの確認手順：

1. ニクロム線用の負荷を切り離して書き込み、出力を測定できる状態にする。
2. ピン挿入状態で起動し、`Fp=1`と`Ph=5`を確認する。
3. ピンを抜き、高度条件または気圧更新停止＋時間条件の成立で`Ph=0`になることを確認する。正常な低高度測定が続く場合、時間だけでは開始しないことも確認する。
4. 第3節の時間・出力・LEDと、通電段階終了時の出力LOWを確認する。
5. 別の起動で、開始条件待ちの再挿入と抜き直しにより、待ち時間と高度回数が最初からになることを確認する。
6. 各警告段階・通電段階での再挿入により出力が停止し、抜き直しても再開始しないことを確認する。
7. 起動時からピンを抜いたままにした場合に開始しないことを確認する。

ホストテストとビルドの実施結果は[検証資料](Separation_implementation_and_usage.md#検証)を参照してください。実機の割り込み遮断、GPIO波形、実電流・機械的な分離は未検証です。

## 7. ログとテレメトリ

開始要求時のログは`Flight pin removed and separation start conditions met; sequence requested`、拒否時は`Separation sequence start rejected`です。状態変化は`Nichrome phase: Startup`などで確認できます。割り込み内ではログを出しません。

Nichromeのcomponent IDは36（`0x24`）、unit IDは現在`0x41`です。

| パケット | 内容・送信周期 |
| --- | --- |
| Nichrome `I` | `Vi`：mV、`Ii`：mA、`Pi`：mW、`Ts`：ms。初期1 Hz、シーケンス開始後10 Hz |
| Nichrome `S` | 下表の状態。変化時および約1秒ごと |
| FlightPin `F`（component `0x50`） | `Fp`：0/1、`ET`：状態継続ms、`TS`：測定時刻ms。1 Hz |

| `S`のエントリ | 意味 |
| --- | --- |
| `Ph` | 第3節の状態番号 |
| `Et` | 現在フェーズの経過ms |
| `St` | シーケンス開始からの経過ms |
| `Rt` | 警告段階での通電までの予定残りms |
| `Bz` | HIGH側のみ有効な状態 |
| `Ig` | HIGH側・LOW側とも有効な状態 |
| `Hi`・`Lo`・`Nl` | HIGH側・LOW側・NORMAL LEDのソフトウェア上の出力状態 |
| `Ok` | Nichrome初期化済み、かつ状態が`Fault`ではない |
| `Ts` | 送信時刻ms |

**開始条件待ちの時間は`Rt`に含まれません。** この間は`Ph=5`、`Rt=0`です。`ET`はFlightPinの状態継続時間であり、Mainの待ち時間そのものではありません。`Rt`は通電中の残り120秒も表示しません。

10 Hz化は通電開始時ではなくシーケンス開始時です。Doneへ移行すると測定・送信を1 Hzへ戻します。アボートでは1 Hzへ戻しません。`Hi`・`Lo`・`Nl`は電気的な読み戻しではなく、`Ok`も全コンポーネントや分離成功を示す値ではありません。

SerialBusとLoggerを起動します。SDへの保存はLoggerの正常動作が前提です。現在はCANの`begin()`とTelemeterが無効のため、CAN・Wi-Fi経由の転送を前提にしないでください。

## 8. 動かないとき

| 症状 | 確認すること |
| --- | --- |
| 抜いても始まらない | 挿入・抜去認識、現在GPIO LOW、高度条件または気圧停止＋1時間条件、途中のリセット |
| 中止後に抜き直しても始まらない | 同一ブート中の再開始禁止による正常動作 |
| 待機中に`Rt=0`のまま | 開始条件待ちの残り時間は送信していない |
| ERROR LEDが点灯したまま | Nichrome初期化やISR登録でsetupが終了していないか |
| `Ok=true`なのに開始しない | `Ok`は開始条件やISR登録の成功を表さない |
| Nichromeの状態通知が来ない | INA226初期化・校正、タスク生成などの失敗。タスク起動前の失敗は`Fault`通知やLED点滅も出ない場合がある |
| 起動直後に停止し、パケットが出ない | [NVSのモジュールID不一致](../nvs_module_id_troubleshooting.md)も確認 |
| CANやサーバーへ届かない | 現構成ではCANとTelemeterは無効 |

この資料の配線根拠は現行コードです。基板との一致は別途確認が必要です。特にFlightPinはGPIO 2で、`Serial0.setPins(2, 1)`にも2が指定されています。また、LiPoPowerとNichromeは同じWire上のINA226アドレス`0x4D`をそれぞれ異なる校正値で初期化します。配線・周辺機能の使用状況と計測値への影響は未検証です。
