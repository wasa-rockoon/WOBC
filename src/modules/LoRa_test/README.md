# LoRa_test: ESP32-S3でチャンネル16を受信

LoRa2026基板の **LoRa2 / U401** を使い、受信したWCPPパケットにRSSI (`Ss`) を追加してUSB経由でPCへ転送する。LoRa1はこのプログラムでは使用しない。

## 接続・通信設定

| 信号 | ESP32-S3のGPIO |
| --- | --- |
| TX → E220 RXD | 7 |
| RX ← E220 TXD | 18 |
| AUX / M0 / M1 | 8 / 5 / 6 |
| アンテナV1 / V2 | 9 (HIGH) / 10 (LOW) |
| STAT / ERR | 42 / 41 |

- 無線: チャンネル **16**、SF9、BW125kHz、透過モード、アドレス `0xFFFF`。
- E220のUART: 設定中9600bps、受信中115200bps、8N1。
- 送信フレーム: 既存の `E220::sendTransparent()` と同じ `[長さ][WCPP][CRC8]`。
- PC: 既存のWCPP対応アプリで受信基板のCOMポートを115200bpsで開く。通常のシリアルモニター向けの文字出力ではない。
- USB出力: `[Ss追加後のWCPP][再計算したCRC8][0x00]`。送信元・宛先・パケットID・ペイロードを保持する。

送信側もチャンネル16に合わせる。リポジトリのTrackerはチャンネル3、MissionBusは11なので、それらを送信機に使う場合は送信側の設定変更と再書き込みも必要。

## ビルド・書き込み

```powershell
pio run -e LoRa_test
pio run -e LoRa_test -t upload --upload-port COM番号
```

`COM番号` を受信基板の実際のポート名に置き換える。

## 動作確認

1. LoRa2側のアンテナを接続して起動する。
2. WCPPアプリのログで `LoRa2 ready (channel 16).` を確認する。モジュールIDは `0x4C`、受信コンポーネントIDは `0x10`。起動時のログを取り逃した場合は、PCアプリを接続した状態で基板をリセットする。
3. 送信機を動かし、元のテレメトリと受信強度 `Ss` を確認する。

初期化に失敗するとERRが点灯したままになり、`lrIN` の `Ms` に失敗した処理とAUX・M0/M1・UART未読数を出力する。`channel-read` / `channel-check` はチャンネル16の読み戻し確認の失敗。
`lrSZ` はフレーム長、`lrCS` はチェックサムの不一致。STATは内部パケット数の変化でも点滅するため、無線の受信確認には `Ss` 付きテレメトリを使う。

実機での無線通信確認は別途必要。
